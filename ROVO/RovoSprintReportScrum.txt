## STEP 1 — FETCH SPRINT ISSUES

Run this JQL query (single line, no breaks):
  project = '{{projectKey}}' AND sprint = '{{sprintName}}' AND issuetype not in subTaskIssueTypes() ORDER BY status DESC, resolved DESC

If it returns 0 results, try:
  project = "{{projectKey}}" AND sprint = "{{sprintName}}" AND sprint not in futureSprints() AND issuetype not in subTaskIssueTypes() ORDER BY statusCategory, resolved DESC

Rules:
- Set fieldsToReturn = "*all" when calling the search tool.
- ONLY use project {{projectKey}}. Never search other projects.
- If no results after both queries, report "No issues found for {{projectKey}} / {{sprintName}}".

---

## STEP 2 — BUILD TWO LISTS

After fetching results, discard immediately:
- Any issue whose type is a sub-task variant (Sub-task, Sub Test, Sub Test Execution, Technical task subordinate, etc.)
- Any issue whose type is Test, Test Case, or Test Execution.

From the remaining issues, build:

**DONE_LIST**: issues with Status = Done, Closed, or Resolved.
**PENDING_LIST**: ALL other issues (In Progress, In Development, Review, To Test, Blocked, Waiting, On Hold, To Do, Open, etc.).

No issue may appear in both lists. No sub-tasks in either list.

---

## STEP 3 — CLASSIFY DONE_LIST BY WORK CATEGORY

Use ONLY the exact value of the Jira field "Work Category" on each issue. Never infer it from the summary, labels, or components.

**KEY GOALS** (business): Work Category is exactly one of:
  Client Services | Product:Feature | Product:Discovery | Deprecation

**KEY TECHNICAL GOALS** (technical): Work Category is exactly one of:
  Enabler | Technical Debt | Quality Assurance | Quality:L3 Support | L3 Support | Risk Mitigation | Team Management | SysOps/DevOps

**NO WORK CATEGORY**: Work Category field is empty or missing → add to "Issues without Work Category" list.

Issues with any other Work Category value → exclude from Goals sections; add to "Issues without Work Category" list.

---

## STEP 4 — GROUP BY EPIC

For each issue in KEY GOALS and KEY TECHNICAL GOALS:

1. Look up the issue's Epic Link field to find its parent Epic.
2. If it has an Epic → fetch that Epic's Summary/title from Jira. Use the Epic's title as the group header. NEVER use the Epic ID (e.g., DID-XXXXX) as a header.
3. If it has NO Epic → use the Work Category value as the group header.
4. All issues sharing the same Epic go into ONE bullet. Do not split them.
5. STRICT MEMBERSHIP RULE: A bullet may ONLY contain issue IDs that are in KEY GOALS (or KEY TECHNICAL GOALS). NEVER add an issue to a bullet just because it shares the same Epic with a qualifying issue. If an issue is in PENDING_LIST, it is FORBIDDEN from appearing in any Goals bullet, even if its Epic appears in Goals.
6. COMPLETENESS CHECK — Before writing: go through every issue in KEY GOALS one by one and confirm it appears in a bullet. Do the same for KEY TECHNICAL GOALS. If any issue is missing, add it to its Epic group. Zero omissions allowed.

---

## STEP 5 — WRITE THE REPORT

Output ONLY the report below. Do not print the steps, lists, or methodology.
Answer in English.
